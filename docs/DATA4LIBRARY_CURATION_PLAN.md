# 도서관 정보나루 기반 큐레이션 계획

기준 문서: `도서관정보나루_API_Manual.pdf` v20260210

## 범위

이번 단계에서는 도서관 정보나루만 사용한다. 국립중앙도서관과 YouTube 연동은 후속 단계로 미룬다.

정보나루의 원본 분류나 인기순위를 그대로 복제하지 않고, 여러 신호를 조합해 “다음책”의 발견용 카테고리로 변환한다. 각 결과에는 반드시 산출 근거를 함께 표시한다.

서비스 범위는 “무엇을 읽을지 모를 때 발견을 돕는 것”까지다. 도서관 검색, 소장 여부, 대출 가능 여부와 대출 동선은 제품 화면에 연결하지 않는다.

## 현재 사용하는 API

| 정보나루 API        | 용도                                             | 서비스 내부 경로/사용처                  |
| ------------------- | ------------------------------------------------ | ---------------------------------------- |
| `srchBooks`         | 제목·저자·ISBN·키워드 검색                       | `/api/library/books`                     |
| `loanItemSrch`      | 기간·연령·지역·KDC·ISBN 부가기호별 대출 순위     | `/api/library/rankings`, 데이터 큐레이션 |
| `hotTrend`          | 최근 7일 대출 순위 급상승                        | 데이터 큐레이션                          |
| `monthlyKeywords`   | 전월 급상승 도서 기반 TF-IDF 키워드              | 데이터 큐레이션                          |
| `keywordList`       | ISBN별 핵심 키워드(최대 50개)                    | `/api/library/signals/{isbn}`            |
| `usageAnalysisList` | 12개월 대출 추이·함께 빌린 책·마니아/다독자 추천 | `/api/library/signals/{isbn}`            |

모든 외부 요청은 서버에서 수행하며 `authKey`는 브라우저에 전달하지 않는다. JSON 응답을 위해 `format=json`을 사용한다.

## 정보나루가 제공하는 주요 분류 축

- KDC 대주제: 총류, 철학, 종교, 사회과학, 자연과학, 기술과학, 예술, 언어, 문학, 역사
- KDC 세부주제: `00`~`99` 코드
- 연령: 영유아, 유아, 초등, 청소년, 20대, 30대, 40대, 50대, 60세 이상 및 학년 세분
- 성별: 남성, 여성, 미상
- 지역: 17개 광역시도 및 세부지역
- ISBN 부가기호: 교양, 실용, 여성, 청소년, 학습참고서, 아동, 전문
- 시간 신호: 지정 기간 대출순위, 최근 7일 급상승, 최근 12개월 대출 추이, 전월 키워드
- 관계 신호: 함께 대출된 책, 마니아 추천, 다독자 추천

## 독자 대상과 아동서 편향 방지

일반 추천의 기본 대상은 성인 독자다. 보호자 계정의 다권·시리즈 대출 때문에 아동서 대출량이 실제 성인 독자의 관심보다 크게 집계될 수 있으므로 대출순위를 그대로 사용하지 않는다.

- 기본 허용: ISBN 부가기호 `0 교양`, `1 실용`, `2 여성`, `9 전문`
- 기본 제외: `4 청소년`, `5 학습참고서`, `6 초등`, `7 아동`
- 부가기호가 없거나 해석할 수 없는 책도 일반 추천에서는 제외
- 동일 시리즈는 한 화면에 한 권만 허용
- 좋은 어린이 문학은 대출량으로 자동 선정하지 않고, 별도 검증 목록이 생긴 뒤 낮은 비율의 의도적 우연으로만 제공

## 현재 구현한 다음책 카테고리

### 1. 지금 막 떠오른 책

- 입력: `hotTrend`
- 규칙: 검색일 기준 최근 3일 결과에서 ISBN 중복을 제거하고 상승폭이 확인된 책을 노출
- 표시 근거: 기준일과 전주 대비 순위 상승폭
- 의도: 누적 베스트 순위보다 최근의 변화 포착

### 2. 세대를 건너 함께 읽힌 책

- 입력: 최근 90일 `loanItemSrch` 20~~29세, 50~~59세 결과
- 규칙: 두 연령대 상위 100권의 ISBN 교집합을 두 순위의 합으로 정렬
- 표시 근거: 20대 순위와 50대 순위
- 의도: 한 연령대에 갇히지 않는 공통 관심 발견

### 3. 다시 펼쳐진 오래된 책

- 입력: 최근 90일 전체 `loanItemSrch`
- 규칙: 출간 후 10년 이상 지난 책만 선별
- 표시 근거: 출간연도와 최근 90일 대출순위
- 의도: 신간 중심 노출에서 벗어나 다시 읽히는 책 발견

### 4. 문학 밖, 분야를 건너는 산책

- 입력: 최근 90일 `loanItemSrch`
- 조건: KDC `0~7, 9`, ISBN 부가기호 `교양·실용·전문`
- 규칙: KDC 대주제가 겹치지 않도록 분야별 한 권씩 선별
- 표시 근거: KDC 분류명과 대출순위
- 의도: 문학 편중과 동일 장르 반복 완화

### 5. 출판사별로 펼쳐 보는 선반

- 입력: 최근 90일 전체 `loanItemSrch`
- 규칙: 대출 상위 100권을 출판사명으로 묶고 서로 다른 책이 2권 이상인 출판사만 선별
- 정렬: 포함된 책 수가 많은 순, 동률이면 가장 높은 대출순위 순
- 표시 근거: 출판사명과 각 책의 최근 90일 대출순위
- 의도: 한 출판사가 만드는 목록의 결을 따라 책을 발견

### 이달의 독서 기류

- 입력: `monthlyKeywords` 전월 데이터
- 규칙: 가중치 상위 12개 키워드를 노출
- 주의: 키워드는 추천 이유가 아니라 그달의 관심 흐름을 설명하는 보조 신호로 사용

## 데이터 흐름

1. 브라우저가 `/api/discovery/categories`를 요청한다.
2. 서버가 정보나루 API 6개 요청을 병렬 실행한다.
3. ISBN을 공통키로 중복 제거·교집합·필터링을 수행한다.
4. 자체 카테고리 제목, 설명, 책별 근거를 붙여 반환한다.
5. 응답은 브라우저 15분, CDN 6시간 캐시하며 24시간 동안 stale 응답을 허용한다.
6. 일부 외부 요청이 실패하면 성공한 카테고리는 유지하고 `warnings`에 누락 신호를 기록한다.

## 후속 작업 순서

### 1단계: 현재 MVP 운영 검증

- 카테고리별 클릭률, 저장률, “관심 없음” 비율 기록
- API 지연·오류율 및 일일 호출량 측정
- 책 중복, 아동서 편중, 특정 출판사 편중 모니터링

### 2단계: 사용자별 카테고리

- 사용자가 저장/읽음/관심 없음으로 표시한 ISBN의 KDC와 키워드 집계
- 익숙한 KDC 70% + 인접 KDC 20% + 반대편 KDC 10%로 탐색 비율 구성
- `usageAnalysisList`의 함께 빌린 책을 1차 후보로 사용
- 마니아 추천과 다독자 추천을 분리해 “깊게 파기”와 “넓게 건너기”로 제공
- 이미 읽음·관심 없음·최근 본 ISBN은 제외

### 3단계: 출판사와 고전 큐레이션

- 출판사별 책 목록과 KDC 분포를 이용해 출판사의 선반 확장
- 출판사별 동일 저자·시리즈 중복을 줄이고 서로 다른 분야를 우선 노출
- 고전은 오래된 책과 분리하고 공신력 있는 작품 목록과 편집자 검수를 거쳐 확정
- 고전 작품과 여러 번역본·개정판 ISBN을 작품 단위로 통합
- 정보나루는 고전 판정이 아니라 현재 읽히는 판본을 찾는 보조 신호로만 사용

### 4단계: 랜덤 발견과 품질 고도화

- 월별 순위 스냅샷을 D1에 저장해 “꾸준히 오래 읽힌 책”을 실제 시계열로 계산
- 카테고리별 최소 다양성 규칙: 동일 KDC·출판사·저자 최대 비율 제한
- 읽음·관심 없음·최근 본 책을 제외한 가중 랜덤 추천 적용
- 추천 산식 버전과 입력 근거를 저장해 결과 재현 가능성 확보
- 편집자 검수 화면에서 카테고리 숨김, 책 제외, 설명 수정 지원

## 완료 기준

- API 키가 클라이언트 응답과 로그에 포함되지 않는다.
- 모든 책에 ISBN, 출처, 산출 이유가 존재한다.
- 외부 API 일부 실패가 전체 화면 실패로 이어지지 않는다.
- 카테고리 이름이 원본 데이터가 실제로 증명하는 범위를 넘어서지 않는다.
- 테스트에서 날짜 범위, 교집합, 출간연도, KDC 다양성 규칙을 검증한다.
